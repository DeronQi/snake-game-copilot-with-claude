# AI 演示模式：哈密顿环 + 安全抄近路

本文说明 `ai.js` 中 AI 的算法、为什么它**保证通关**，以及实测效率。

## 1. 目标

普通的「贪心 + 寻路」AI 能玩，但不能保证通关：蛇越来越长时，它会把自己困死。这里的要求更强：**任何随机果实序列下，都要填满 20×20 的全部 400 格**。

## 2. 哈密顿环

哈密顿环是一条经过每个格子恰好一次、首尾相邻的闭合路径。只要蛇永远沿着它走，就绝不会撞到自己，最终一定能填满棋盘，只是很慢。

`buildCycle(cols, rows)` 的构造方式（要求列数为偶数）：

1. 从 `(0, 0)` 沿第 0 列向下走到底；
2. 第 1 ~ 19 列在第 1 ~ 19 行之间蛇形往返（奇数列向上，偶数列向下）；
3. 最后一列（第 19 列，奇数列）向上走到第 1 行后，沿第 0 行向左走回 `(0, 0)` 闭合。

以 6×4 为例（每格箭头表示从该格走向环上的下一格）：

```
↓ ← ← ← ← ←
↓ → ↓ → ↓ ↑
↓ ↑ ↓ ↑ ↓ ↑
→ ↑ → ↑ → ↑
```

每个格子得到唯一的**环序号** `order[idx] ∈ [0, 400)`，`path[k]` 是序号为 `k` 的格子。`verifyCycle` 会检查：覆盖每格恰好一次，且相邻序号（包括首尾）在网格上相邻。

记 `fwd(a, b) = (order[b] − order[a]) mod N`，表示从格 `a` 沿环向前走到格 `b` 的步数。

## 3. 不变式

> 从尾到头读蛇身，各节的环序号沿环**严格前进**，且总跨度 < N。

等价地说：整条蛇落在环上的区间 `[尾, 头]` 内（区间里可以有空洞），而区间 `(头, 尾)`（从头沿环往前走到尾之间的格子）**一定全空**。

初始状态（第 10 行三节、向右）满足这个不变式；`isOrdered(game)` 用于检查它，模拟脚本在每一步后都会校验。

## 4. 安全规则

设

- `step = fwd(头, 目标格)`：目标格沿环在头前方多少步；
- `gap = fwd(头, 尾)`：尾巴沿环在头前方多少步。

AI 只考虑满足下列条件的相邻格：

| 情况 | 条件 | 理由 |
| --- | --- | --- |
| 不吃果实 | `1 ≤ step ≤ gap` | `step < gap` 时目标在 `(头, 尾)` 区间内，必空；`step = gap` 时目标就是尾巴，这一步尾巴会移走 |
| 吃果实 | `1 ≤ step < gap` | 吃果实时尾巴不动，连尾巴格也不能踩 |

走完之后新头仍在旧尾之前，不变式保持。

### 4.1 为什么永不咬到自己

不变式保证 `(头, 尾)` 区间为空，安全规则保证头只落进这个区间（或刚好移走的尾巴格）。头永远追不上尾巴。

### 4.2 为什么永不卡死

沿环的下一格 `step = 1`。当蛇长 < N 时 `gap ≥ 1`：

- 若 `gap > 1`，下一格在空区间内，合法；
- 若 `gap = 1`，下一格就是尾巴。果实只会刷在空格上，不可能在尾巴格，所以这一步一定不吃果实，尾巴会移走，合法。

所以每一步至少有一个合法走法。实现里还有兜底分支，理论上不会走到。

### 4.3 为什么一定通关

- 每一步，头沿环至少前进 1 格（`step ≥ 1`），且不会越过尾巴。
- 果实总在某个空格上。空格要么在 `(头, 尾)` 区间里，要么是 `[尾, 头]` 区间里的空洞。
- 在 `(头, 尾)` 区间里的果实，头沿环前进时一定会经过它；在空洞里的果实，随着尾巴前进，空洞会落到尾巴后面，从而进入 `(头, 尾)` 区间。
- 因此每个果实都会在有限步内被吃到，蛇长单调增长，直到 400 格。

## 5. 抄近路

只沿环走平均每个果实要 ~99 步。所以在所有合法走法中择优，排序键为：

1. **能直接吃到果实**的优先；
2. 走完后**沿环到果实的剩余步数**更少的优先；
3. 到果实的**曼哈顿距离**更小的优先；
4. **环步长**更大的优先（同等条件下跳得更远）。

抄近路时，蛇身在环上会留下空洞，但不变式不受影响。

## 6. 门控

蛇很长时，跳格会在身后留下零散空洞。果实一旦刷在空洞里，就要绕将近一整圈才能吃到。所以：

> 空地 < 蛇长 × 1.25 时，禁止跳格：只允许沿环走 1 步，或直接吃到果实。

若门控后没有合法走法，就退回「不门控」版本重新选择，保证不卡死。

```text
decide(game):
  best = pick(game, gate = true)
  if best 为空: best = pick(game, gate = false)
  if best 为空: return fallback(game)       # 理论上不会发生
  return best.方向

pick(game, gate):
  gap = fwd(头, 尾)
  gated = gate 且 (N − 蛇长) < 蛇长 × 1.25
  对每个相邻格 c:
    跳过越界格、被占用格（可移走的尾巴除外）
    step = fwd(头, c)
    若 吃果实 且 step ≥ gap: 跳过
    若 不吃果实 且 step > gap: 跳过
    若 gated 且 不吃果实 且 step ≠ 1: 跳过
    记录候选 [吃到果实, fwd(c, 果实), 曼哈顿(c, 果实), step]
  按排序键返回最优候选
```

## 7. 效率数据

`node tools/analyze-ai.cjs`（10 个种子，全部通关）：

| 方案 | 平均总步数 | 相对基线 | 相对曼哈顿下界 |
| --- | ---: | ---: | ---: |
| 纯绕环基线 | 39,277 | 100.0% | 8.61× |
| 抄近路 · 不门控 | 38,681 | 98.5% | 8.48× |
| **本策略（门控 1.25）** | **32,938** | **83.9%** | **7.22×** |
| 曼哈顿下界 | 4,563 | 11.6% | 1.00× |

每个果实的平均步数，按果实序号分阶段：

| 阶段 | 果实区间 | 纯绕环基线 | 不门控 | 本策略 | 曼哈顿下界 |
| --- | --- | ---: | ---: | ---: | ---: |
| 前 25% | #1 ~ #99 | 171.7 | 33.3 | 33.3 | 13.2 |
| 中段 50% | #100 ~ #297 | 99.2 | 98.0 | 97.2 | 12.3 |
| 后 25% | #298 ~ #397 | 26.3 | 159.8 | 103.9 | 8.1 |
| 全程 | #1 ~ #397 | 98.9 | 97.4 | 83.0 | 11.5 |

解读：

- **前期**蛇短、空地多，抄近路效果显著（每果实 33 步，基线 172 步）。
- **中段**蛇身空洞增多，安全区间变窄，收益有限。
- **后期**不门控会因空洞变得比基线还慢（160 步）；门控把它降到 104 步，但仍慢于基线（26 步）。基线在后期快，是因为它的蛇身始终紧密排列，空格都在头的正前方。
- 曼哈顿下界忽略了蛇身阻挡，不可能达到，只作参考。

> 后期仍有优化空间，例如蛇长超过某个阈值后完全切换为纯沿环，或在门控时优先选择不会制造空洞的格子。当前实现严格按需求的门控规则，保证正确性优先。

## 8. 浏览器中的速度

- 倍速 ×1 / ×4 / ×16 / ×64 在当前难度和等级的步速上加速；MAX 固定为 **1400 步/秒**（`game.js` 中的 `AI_MAX_SPS`）。
- 平均约 3.3 万步，MAX 档约 **24 秒**通关；端到端测试中 4 种视口实测 22 ~ 26 秒。
- 主循环用固定步长累加器，一帧最多推进 600 步，渲染与逻辑解耦，帧率保持 60 fps。
- 高倍速时（×16 及以上）自动跳过逐果实音效、震动和光环动画。

## 9. 与玩家模式切换

- 演示期间玩家的方向输入被忽略，暂停、继续、全屏照常。
- 游戏中途打开 🤖：先用 `isOrdered` 检查当前蛇身是否满足不变式，满足就直接接管，否则开一局新的 AI 演示。
- 关闭 🤖 后玩家立即接管当前这局。
