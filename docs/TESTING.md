# 验证与测试

项目没有测试框架依赖，全部验证脚本都是独立的 Node / Python 文件，放在 `tools/` 下。每个脚本失败时以非 0 退出码结束，可直接接入 CI。

| 脚本 | 运行环境 | 作用 |
| --- | --- | --- |
| `tools/simulate-ai.cjs` | Node | AI 无头模拟，断言 4 档难度 × ≥5 个种子全部通关 |
| `tools/analyze-ai.cjs` | Node | AI 效率分析：纯绕环基线 / 本策略 / 曼哈顿下界，分阶段统计 |
| `tools/verify.cjs` | Node + Playwright | 浏览器端到端：4 种视口 + `file://`，像素识别真实自动游玩 |
| `tools/verify-sw-update.cjs` | Node + Playwright | Service Worker 离线、旧缓存、发版自动更新 |
| `tools/make_icons.py` | Python + Pillow | 生成 PWA 图标（输出确定，可重复执行） |
| `tools/screenshots.cjs` | Node + Playwright | 生成 README 截图 |
| `tools/serve.cjs` | Node | 零依赖静态服务器，上面的浏览器脚本都用它起临时服务 |

环境准备：

```bash
npm i -D playwright && npx playwright install chromium   # 只有浏览器脚本需要；也可全局安装
pip install pillow                                        # 只有图标脚本需要
```

## simulate-ai.cjs

```bash
node tools/simulate-ai.cjs        # 每档 5 个种子
node tools/simulate-ai.cjs 20     # 每档 20 个种子
```

- 直接 `require('../ai.js')`，和浏览器使用同一份规则与 AI。
- 先校验哈密顿环（覆盖 400 格、首尾闭合）。
- 每档难度用不同的固定种子（`mulberry32`），结果可复现。
- 每一步后校验 AI 不变式（蛇身沿环有序）。
- 断言每局都是：通关、蛇长 400、得分 397。
- 输出步数、CPU 耗时、按 ×1 速度换算的游戏时长、按 MAX（1400 步/秒）估算的浏览器内通关时间。

### 如何「真正自动游玩」

脚本不读取游戏内部状态，而是读取 canvas 像素：在每格中心采样，按颜色识别蛇头、蛇身和果实。然后用「贪心靠近果实 + 洪水填充避开死路」决定方向，再通过该环境的真实输入方式发送。

### 每个环境的断言

- **布局**（开始界面、游戏中、通关面板各检查一次）：棋盘正方形、完整在视口内、边长 ≥ 短边的 60%、canvas 像素尺寸符合 DPR（上限 2.5）、页面无滚动溢出、顶部按钮与计分可见、弹层无需内部滚动；竖屏触屏显示方向键，横屏隐藏方向键，桌面显示键盘提示。
- **难度**：分段选择器只高亮一项；刷新后保持；`localStorage` 写入正确。
- **暂停 / 恢复**：暂停后蛇头位置不变，标题为「已暂停 · 得分 0 · 贪吃蛇」；恢复后继续移动；窗口失焦自动暂停。
- **自动游玩到 5 分**：计分正确；≥4 分时速度显示 2 级；每吃一个果实 `localStorage` 最高分都已同步；标题实时同步。
- **R 重开**：得分归零，最高分不丢；刷新后最高分仍在。
- **AI**：开始界面有「🤖 看 AI 演示」；演示条和 🤖 按钮状态正确；倍速按 ×1 → ×4 → ×16 → ×64 → MAX 循环；在浏览器内通关，得分 397；通关文案、标题正确；AI 成绩计入最高分；像素确认 400 格全被蛇身占据。
- **控制台**：0 条 error、0 个页面异常。

`file://` 环境检查：页面与 `ai.js` 加载成功、可以自动游玩到 3 分、控制台 0 报错。

## verify-sw-update.cjs

```bash
node tools/verify-sw-update.cjs
```

用 `tools/serve.cjs` 起临时服务器，并通过它模拟断网（直接断开连接）和发版（替换 `sw.js` 响应）。缓存名和资源清单直接从 `sw.js` 解析，与实现保持同步。

| 阶段 | 断言 |
| --- | --- |
| 首次访问 | SW 注册并接管；`updateViaCache === 'none'`；缓存名正确；预缓存全部资源（含 `?v=1`）；首次安装不自动刷新 |
| 断网刷新 | 页面、脚本、样式都从缓存加载；可以开始游戏 |
| 旧缓存投毒 | 向 Cache Storage 写入旧版 `game.js`、`style.css`、`index.html` 后在线刷新，必须加载到新代码，且缓存被新内容覆盖；再次断网刷新仍是新代码 |
| 模拟发版 | `sw.js` 的 `VERSION` 变化后刷新：新 SW 接管，页面**恰好自动 reload 一次**，旧缓存被清理，页面仍受 SW 控制 |
| 全程 | 页面脚本 0 异常；在线阶段控制台 0 报错 |

最近一次结果：**19 / 19 通过**。

## make_icons.py

```bash
python tools/make_icons.py
```

生成 `icons/icon-192.png`、`icons/icon-512.png`、`icons/icon-maskable-512.png`。不使用随机数和时间戳，连续运行两次输出的文件哈希一致。maskable 图标主体位于中心 56% 区域，满足 80% 安全区要求。

## 手动检查清单

自动化没有覆盖、建议发版前手动确认的项目：

- [ ] Chrome / Edge 地址栏「安装」后以独立窗口启动，图标显示正常
- [ ] 真机手机：滑动、方向键手感，吃果实 / 死亡震动，刘海屏安全区
- [ ] 系统开启「减少动态效果」后，无震屏、无果实脉动
- [ ] 声音：首次点击后有开始音效，M / 🔊 切换静音并在刷新后保持
